# ADR-0027 — 픽업 완료 기록을 서버에 저장

- 상태: **채택** (2026-11-14)
- ADR-0008의 "픽업이 끝나면 서버에는 익명 정보만 남긴다"에 예외를 둔다. 끝난 계획(`PICKUP_PLAN`)의 익명화는 그대로다.
- 기능 명세 P-13·RM-C-P2·RM-V11("도착 기록은 차 안에만 저장하고 서버로 보내지 않는다")과 픽업 완료 시안 문구 「기록은 이 차에만 저장되고 서버로 보내지 않아요」와 다르다. 명세·시안·개인정보 고지 수정은 PM에 넘긴다.
- 사용자가 2026-11-14에 고른 결정이다(T94).

## 결정

- 집에 도착해 앱이 픽업 완료를 보내면 서버는 그날 기록을 `PICKUP_RECORD`에 저장한다. 집 도착 시각, 총 소요 분, 대기 분, 출발 장소(이름·좌표)와 시각, 탑승 장소(이름·좌표)와 시각, "다음부터 묻지 않고 저장" 여부다.
- 기록은 계정의 시간표 요일(`TIMETABLE_DAY`)마다 하나만 둔다. 다시 저장하면 덮어쓴다. 같은 일정·요일의 다음 픽업에서 앱이 바로 읽어 쓰기 위한 것이라 최신 한 건만 있으면 된다.
- 기록은 끝난 계획과 칸·FK로 잇지 않는다. 이으면 익명화한 계획이 다시 계정으로 이어진다.
- 시간표 요일이나 시간표를 지우거나 계정을 지우면 기록도 `DELETE_YN`을 켜고 장소 이름·좌표를 비운다(ADR-0008의 삭제 규칙과 같다).
- 탑승 기록 응답에 집까지 경로와 아이 이름·탑승 시각·탑승 장소를 담는다. 탑승을 기록하는 트랜잭션에서 계획이 익명화되므로 익명화 전에 읽은 값을 응답으로 돌려준다. 이 값은 따로 저장하지 않는다.

## 근거

- 사용자 결정(2026-11-14): 다음 픽업 때 출발 시각과 장소를 바로 쓰려면 차를 바꾸거나 다른 차에서 로그인해도 기록이 있어야 한다. 시간표를 서버에 둔 ADR-0008의 근거와 같다.
- 일정·요일마다 최신 한 건만 두어 이동 기록이 날마다 쌓이지 않게 한다.
- 계획과 잇지 않아야 ADR-0008의 익명 기록이 지켜진다.

## 결과

- 서버에 계정별 출발·탑승 장소와 시각이 남는다. 개인정보 수집 항목·보관 기간 고지와 동의(RM-C-P2) 문구를 바꿔야 한다(PM 전달).
- 명세 P-13·RM-V11·RM-C-P2와 시안 문구가 이 결정과 다르다. 명세가 바뀌기 전까지 서버 동작의 근거는 이 ADR이다.
- 기록을 지우는 경로가 늘었다(시간표·요일 삭제, 계정 삭제).
- 기록의 탑승 시각(초 단위)·장소는 그날 끝난 계획의 `BOARD_DT`·`BOARDED` 이벤트 시각·픽업 지점과 같다. 그래서 기록이 있는 날은 익명화한 계획(대기 주차장·정차 이력 등)을 계정에 다시 이을 수 있다. 출발·탑승 장소와 시각은 이미 기록에 계정과 함께 있으므로 사용자가 2026-11-14에 받아들였다(PR #78 리뷰). 끝난 계획의 익명화 규칙은 바꾸지 않는다.
