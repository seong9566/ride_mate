# ADR-0001 — 3계층 구조와 네이밍 규약

- 상태: **채택** (2026-11-09)

## 결정

백엔드는 ASP.NET Core Web API(.NET 10)로 만들고 아래 구조를 쓴다.

- Controller → Service → Repository 3계층. 의존은 이 방향 하나뿐이다.
- Repository는 partial 파일 3개(`.cs`·`.EF.cs`·`.SQL.cs`)로 나눈다.
- 폴더는 `{레이어}/v1/{도메인}/`으로 맞춘다.
- 네이밍: DTO 프로퍼티는 camelCase, PK는 `{도메인}Seq`, 불리언은 `Yn` 접미, 메서드 접미사로 레이어를 드러낸다.
- 테이블·컬럼은 대문자 스네이크로 쓰고, 모든 업무 테이블에 감사 컬럼과 소프트 삭제를 둔다.
- 비밀값은 환경변수로 주입하고, 필수 설정이 비어 있으면 기동을 실패시킨다.

## 근거

백엔드 개발자가 1명이고 이미 익숙한 구조다. 코드는 대부분 LLM 에이전트가 쓰므로, 판단 여지가 적고 모든 도메인이 같은 모양인 구조가 유리하다.

## 결과

- 홈의 `~/AGENTS.md`(.NET 9, Pomelo, `AppException`, 단위 테스트)와 여러 곳에서 다르다. `backend/AGENTS.md`가 우선한다.
- 세부 규칙은 `backend/docs/architecture/`와 `backend/docs/coding-style.md`에 있다.
- 처음 정한 구조에서 바꾸거나 더한 것은 [ADR-0003], [ADR-0004], [ADR-0005]에 적었다.
