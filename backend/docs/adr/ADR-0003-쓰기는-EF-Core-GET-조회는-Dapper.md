# ADR-0003 — 쓰기는 EF Core, GET 조회는 Dapper

- 상태: **채택** (2026-11-09)

## 결정

GET API의 조회(목록·상세·검색·집계)에는 ORM을 쓰지 않고 Dapper로 SQL을 직접 쓴다. EF Core는 등록·수정·삭제에만 쓴다. 수정·삭제할 대상 엔티티를 PK로 불러오는 것은 쓰기의 일부이므로 EF Core로 한다.

## 근거

쿼리를 직접 튜닝할 수 있고 더 빠르다. STSP 표준은 "PK 단건 조회는 EF Core, JOIN이 2개 이상인 읽기만 Dapper"였는데, 조회를 전부 Dapper로 넓혔다.

## 결과

- 조회 SQL마다 `DELETE_YN = FALSE` 조건과 DTO 프로퍼티에 맞춘 별칭을 손으로 챙겨야 한다. 빠뜨려도 컴파일과 실행이 통과한다.
- Dapper는 DbContext의 커넥션을 같이 쓴다. 한 요청에서 병렬로 쓰거나 EF 트랜잭션 안에서 Dapper를 부르는 경우는 아직 다루지 않았다. 그런 도메인이 생길 때 정한다.
