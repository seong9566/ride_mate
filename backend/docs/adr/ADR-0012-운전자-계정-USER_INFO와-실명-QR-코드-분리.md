# ADR-0012 — 운전자 계정 USER_INFO와 실명, QR 코드 분리

- 상태: **채택(일부 대체 → ADR-0014, ADR-0016)** (2026-11-10)
- ADR-0008을 보완한다. 아이 계정은 여전히 없다.
- 운전자 이름(실명·가리기)은 ADR-0014로, 호칭 `CALL_NAME`은 ADR-0016으로 대체됐다.

## 결정

- 계정 테이블 이름을 `PARENT`에서 `USER_INFO`로, PK를 `PARENT_ID`에서 `USER_ID`로 바꾼다. 참조하는 칸도 모두 `USER_ID`로 바꾼다.
- 계정은 운전자만 가진다. 아이는 계정 없는 `CHILD`로 둔다. 운전자와 아이를 한 테이블에 넣지 않으므로 둘을 가르는 코드 칸과 공통 코드 테이블은 만들지 않는다.
- 운전자 실명 `USER_NAME`을 가입할 때 필수로 받는다. 형식은 `CHILD_NAME`과 같은 `VARCHAR(50)`이다. 화면에는 성만 남기고 가린다.
- 호칭 `CALL_NAME`은 자유 입력으로 둔다.
- QR 로그인은 비밀 값을 둘로 나눈다. 차량이 보관하는 `device_code`(`DEVICE_CODE_HASH`)와 QR에 담는 `user_code`(`USER_CODE_HASH`)이며 둘 다 해시만 저장하고 UNIQUE다. 기존 `QR_TOKEN_HASH`는 `DEVICE_CODE_HASH`로 이름을 바꿨다.

## 근거

- 차를 모는 사람이 부모가 아닐 수 있다(조부모 등). 테이블 이름이 부모를 가리키면 역할과 맞지 않는다.
- 화면설계서 v0.4 RM-V00의 계정 목록은 한 차량에 로그인한 계정을 「김OO」처럼 실명을 가려 구분한다. 호칭만으로는 같은 호칭을 쓰는 계정을 구분할 수 없다.
- QR 하나에 토큰 하나를 담으면 QR을 본 사람이 차량 대신 결과를 받아 갈 수 있다. 차량만 아는 `device_code`가 있어야 QR이 노출돼도 로그인 토큰이 새지 않는다.
- 아직 배포한 DB와 이 칸들을 쓰는 코드가 없어 이름을 바꾸는 비용이 지금 가장 작다.

## 결과

- 실명이 개인정보 수집 항목에 더해진다. 개인정보 고지(RM-C-P1)에 운전자 이름을 넣어야 하고, 계정을 삭제할 때 `USER_NAME`도 빈 문자열로 비운다.
- 실명 입력 화면은 아직 명세서에 없다. 화면이 생기기 전에는 가입 API를 만들 수 없다.
- 감사 컬럼의 역할 값 `PARENT`는 이번에 바꾸지 않았다. 테이블 이름이 아니라 "차량 앱 요청"을 뜻하는 값이다.
- MySQL은 FK가 걸린 칸의 이름을 INPLACE로만 바꾼다. 같은 문장에 칸 추가를 섞거나 CHECK 제약이 있는 테이블이면 COPY가 되어 실패하므로, DDL에서 문장을 나누고 `PICKUP_PLAN`은 FK를 잠시 풀었다가 같은 이름으로 다시 건다.
