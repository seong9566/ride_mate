# ADR-0028 — 출발 안내의 도착 목표는 아이 도착 기준

- 상태: **채택** (2026-11-15)
- ADR-0026의 "도착 목표는 하원 시각보다 `ArriveBeforeEndMin`(기본 10분) 먼저 픽업 장소에 닿는 시각"을 대체한다. 차량 시간·혼잡 보정·일정 지정은 ADR-0026 그대로다.
- 사용자가 2026-11-15에 고른 결정이다(T96).

## 결정

- 픽업 장소 도착 목표 = 하원 시각 + 아이 도보 시간 − 대기 여유. 대기 여유는 `DepartureGuide:WaitBeforeChildMin`(기본 10분)이다. 설정 이름 `ArriveBeforeEndMin`은 `WaitBeforeChildMin`으로 바꾼다.
- 추천 출발 = 도착 목표 − 차량 시간 − 혼잡 보정(ADR-0026 그대로). 혼잡 보정의 비교 시각과 `pickupArrivalDt`도 바뀐 도착 목표를 쓴다.
- 아이 도보 시간은 출발 안내가 고른 픽업 장소의 `pickup.walkMin`이다(카카오 도보 경로, 실패하면 직선 추정).

## 근거

- 기획서 ① 하원 타이밍의 식(도착 = 하원 + 아이 도보 − 대기 여유)에 맞춘다. 부모는 아이가 픽업 장소에 닿기 일정 시간 전에 도착하면 되고, 도보가 긴 장소일수록 일찍 나와 기다릴 필요가 없다.

## 결과

- 추천 출발과 픽업 장소 도착 예상이 도보 시간만큼 늦어진다. 부모는 아이 도착(하원 + 정리 1분 + 도보)보다 대기 여유 + 정리 시간(기본 11분) 먼저 닿는다.
- `slackMin`이 도보 시간만큼 커져 앱이 대기 장소 화면(10분 이상 남음)으로 가는 경우가 늘고, 대기 장소의 대기 시간·예상 요금은 줄어든다.
- 도보 시간 추정이 실제보다 길면 부모의 여유가 그만큼 줄어든다.
- 배정 시각·정원·계획 생성·아이 웹·단속 구역 판정은 바뀌지 않는다. 집 도착 예상은 아이 도착(또는 배정 시각)이 더 늦으면 그대로다.
- 응답 칸은 바뀌지 않아 앱 수정은 없다.
