# ADR-0005 — 응답 계약과 예외 형태

- 상태: **채택** (2026-11-09)

## 결정

- 응답 본문은 `{ message, data, code }`이고 `ApiControllerBase.ToActionResult()`가 `code`를 HTTP 상태로 바꾼다.
- 500 응답과 모델 검증 실패(400)는 ASP.NET Core의 `ProblemDetails` 형태로 나간다. 코드를 바꿔 통일하지 않고, 문서를 실제 동작에 맞춘다.
- 목록은 PK 내림차순 커서 페이징이고 `pageSize`는 1~100이다.
- 수정은 PATCH다. 요청 DTO의 필드는 nullable이고 `null`이거나 빠진 필드는 바꾸지 않는다.
- 요청 DTO에 검증 특성(`[Required]`·`[StringLength]`·`[Range]`)을 붙인다.

## 근거

- `ApiControllerBase`는 STSP 코드 그대로다. 500 분기가 없어 Service의 `code = 500`도 `ProblemDetails`가 된다. 표준 코드를 바꾸지 않기로 했다.
- `pageSize` 상한, PATCH 규칙, DTO 검증은 STSP에 없던 것이다. 큰 `pageSize`의 과도한 조회와 오버플로, 빠진 필드가 기본값으로 덮어써지는 문제를 막으려고 정했다.

## 결과

- 앱은 두 가지 오류 형태(`{ message, data, code }`와 `ProblemDetails`)를 모두 처리해야 한다.
- Service가 넣는 500 오류 문구는 앱에 전달되지 않는다.
- PATCH로 값을 `null`로 지우는 것은 지원하지 않는다.
