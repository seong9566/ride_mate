# ADR-0019 — 문자 사업자는 솔라피, 인증번호는 남용 방어 없이 실발송

- 상태: **채택** (2026-11-11)
- `docs/security.md`에 있던 "실제 문자 사업자를 연결하기 전에 발송 남용 방어를 더한다"를 대체한다.

## 결정

- 문자 사업자는 솔라피다. `ISmsSender`를 `Task<SmsSendResult>`(`Success`, `ResultCode`)를 돌려주도록 바꾸고, 사업자 오류와 타임아웃은 예외가 아니라 `Success = false`로 돌려준다. 요청 취소만 예외로 올린다.
- 설정 `Sms:Provider`로 `Dev`(기본, 실제로 발송하지 않음)와 `Solapi`를 고른다. 휴대폰 인증번호와 픽업 링크 문자가 같은 발송기를 쓴다. `Solapi`이면 `Sms:Solapi:ApiKey`·`ApiSecret`·`Sender`(등록한 발신번호, 숫자만)가 모두 있어야 하고, 하나라도 비었거나 `Provider`가 알 수 없는 값이면 기동할 때 실패한다. 세 값은 비밀값이라 `appsettings.json`에는 빈 값으로만 두고 환경변수(`Sms__Solapi__ApiKey` 등)나 git 제외 설정 파일로 넣는다.
- 인증번호 문자도 실제로 발송한다. 인증번호 발송 남용 방어(IP·기기별 한도, 번호당 시간·일 한도)는 더하지 않고 미룬다. 인증번호 발송은 문자가 실패해도 지금처럼 200을 돌려주고 로그에 결과 코드만 남긴다.

## 근거

- 운영 규모는 하루 100건 미만이고 무료 배포를 전제한다. 국내에는 무료 문자 구간이 없다. 네이버 SENS는 2026-10-01에 무료 구간을 폐지했다.
- 솔라피는 가입 때 300P를 주고, SMS는 18원, LMS는 45원(부가세 별도)이다. 알리고는 발송 서버 IP를 등록해야 해서 고정 IP가 없는 무료 호스팅에 맞지 않는다. 솔라피는 IP를 등록하지 않아도 되는 것으로 보인다. (설계 `2026-11-11-pickup-link-send-design.md` 3절, 사용자 조사 2026-11-11)
- 솔라피 개인 계정의 하루 발송 한도는 50~500건이라, 한도가 곧 비용 상한 역할을 한다.
- 솔라피 연동은 HMAC-SHA256 API Key 인증(`Authorization: HMAC-SHA256 apiKey, date, salt, signature`)으로 `POST https://api.solapi.com/messages/v4/send`를 부른다. 접수 성공은 응답 `statusCode`가 `2000`인 경우로 본다. 타임아웃은 5초다.

## 받아들인 위험

- 번호를 바꿔 가며 인증번호를 부르면 발송 비용을 막을 수 없다. 지금 인증번호 발송은 같은 번호 1분에 한 번뿐이다. 문자 한 건이 SMS 18원, LMS 45원이고 하루 한도(50~500건)와 충전 잔액이 사실상의 상한이다. (사용자 결정 2026-11-11: 위험 감수)

## 결과

- 운영 환경에서 `Sms:Provider`를 `Solapi`로 바꾸고 비밀값 세 개를 환경변수로 넣어야 문자가 나간다. `Dev`는 Development 환경에서만 기동하고, 그 밖의 환경에서 `Dev`이거나 비어 있으면 기동할 때 실패한다(발송하지 않고 성공을 돌려주는 상태로 운영되지 않게 한다).
- 솔라피 계정이 하루 한도나 잔액 부족으로 발송을 보류하면 응답이 `2000`으로 올 수 있다고 문서에 적혀 있다. 이 경우 서버는 접수 성공으로 보지만 문자는 가지 않는다. 운영 전에 솔라피 콘솔에서 잔액과 한도를 확인한다.
- 발송 남용 방어를 더할 때는 새 ADR을 쓰고 이 ADR을 `채택(일부 대체 → ADR-NNNN)`으로 바꾼다.
- 사업자 응답 본문에는 수신 번호가 들어 있을 수 있어 저장하거나 로그에 남기지 않는다. 결과 코드(`statusCode` 또는 `errorCode`)만 남긴다.
