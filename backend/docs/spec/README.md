# 기능 명세서

라이드메이트 MVP 기능 명세서(화면설계서 상세). 화면별 동작·입력 검증·데이터 연동·상태 문구를 정한다.

- 정본은 `feature-spec.xlsx`다. 같은 폴더의 `NN-*.md`는 시트를 그대로 옮긴 생성 파일이므로 손으로 고치지 않는다.
- 명세는 자주 바뀐다. 현재 버전은 `*-개요.md` 첫머리와 `*-변경-이력.md`에서 확인한다. 이 README에 버전을 적지 않는다.
- 명세 값(문구·길이 제한·화면 흐름 등)은 기억이나 이전 대화에서 가져오지 않고, 쓸 때마다 현재 파일에서 다시 읽는다.
- 화면은 Screen ID(`RM-V00`, `RM-M01` 등)로 찾는다: `grep -n "RM-V01-2" docs/spec/*.md`
- 시트 번호(`NN-`)는 시트 순서라 버전마다 바뀔 수 있다. 문서·코드 주석에서 가리킬 때는 시트 이름과 Screen ID·정책 ID(`P-xx`, `D-xx`)를 쓴다.

## 시트

| 시트 | 내용 | 주로 볼 때 |
|---|---|---|
| 개요 | 화면 목록(Screen ID·진입 조건·다음 화면) | 어떤 화면이 있는지 볼 때 |
| 플랫폼 정책 준수 | Pleos 가이드·팀 정책 적용 방식 | 차량 플랫폼 제약이 걸릴 때 |
| 인터랙션 | 버튼·트리거별 동작, 호출 API, 이동 화면 | API 범위·동작을 정할 때 |
| 입력 검증 | 필드별 필수·타입·길이·형식·오류 메시지 | DTO 검증·오류 응답을 만들 때 |
| 데이터 연동 | 데이터 출처·수신 방식·캐시·실패 처리 | 서버가 줄 데이터를 정할 때 |
| 공공데이터 연동 | 서버가 모아 가공할 공공데이터 목록 | 외부 API 연동 |
| 상태 정의 | Empty·오류·예외 상태와 문구 | 응답 code·빈 결과 처리 |
| 팝업·공통 정책 | 계산식·주행 중 제한·링크 만료 등 공통 로직(P-xx) | 정책 로직 구현 |
| 결정 필요 | 팀이 아직 정하지 않은 항목(D-xx) | 아래 규칙 참고 |
| 변경 이력 | 버전별 변경 | 버전 차이 확인 |

이 표에 없는 시트가 생기면 `ls docs/spec/*.md`로 확인하고 이 표에 한 줄 추가한다.

## 읽는 규칙

- 명세 안의 ‘가정’ 값과 `결정 필요` 시트에서 확정되지 않은 항목은 임의로 정하지 않는다. 구현에 필요하면 멈추고 사용자에게 묻는다.
- 명세와 이미 구현된 코드가 다르면 어느 쪽에도 조용히 맞추지 않는다. 다른 점(Screen ID·항목·코드 위치)을 사용자에게 알리고 지시를 받는다.
- 명세와 ADR·`docs/architecture`·`docs/api.md`가 충돌하면 코드 규칙은 ADR·docs를 따르고, 충돌 내용을 사용자에게 알린다. 기획 판단이 필요하면 PRD를 먼저 본다(`AGENTS.md` 첫머리).
- 명세는 앱 화면 기준이다. 차량 SDK·UI만의 동작(주행 규제, TTS 등)은 서버 범위가 아니다.

## 명세 갱신

1. `docs/spec-<버전>` 브랜치에서 `backend/`로 이동해 `python3 scripts/spec-to-md.py <새 명세서.xlsx>`를 실행한다. xlsx를 이 폴더의 `feature-spec.xlsx`로 복사하고 md를 모두 다시 만든다.
2. `git diff -- docs/spec/*.md`로 바뀐 행을 보고, 영향받는 기존 API·DTO·검증을 PR 본문에 적는다. 코드 수정은 이 PR에 넣지 않고 사용자에게 알린다.
3. 시트가 추가·삭제·이름 변경됐으면 위 시트 표를 맞춘다.
